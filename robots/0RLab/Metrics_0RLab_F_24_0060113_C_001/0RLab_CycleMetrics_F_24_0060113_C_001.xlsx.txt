What every column on the Cycle Data sheet means, where it comes from, and how it can mislead you.

[1 empty row]
How to read this data
One row = one sample		tkMetrics emits a sample every nLogPeriodSec (300 s), plus one just before RESET and one at application stop. A row is cumulative since the last RESET — not a snapshot of one plate.
Blank vs n/a		Blank = the software build that produced that sample did not emit the column yet. n/a = the controller emitted "--", meaning the figure is defined but there is not enough data (e.g. LRC p10 needs 10 clean cycles).
Do not compare rates across the Operator hold boundary		Before that column existed, operator-hold time was counted inside the rate. After, it is excluded. Actual s/plate means something slightly different either side.
Only long runs are trendable		Run 3 (134 plates, 11.4 min) is the only sample long enough to judge. The 10–40 plate rows are post-deployment shakedowns.
The bucket sum is the self-check		The eight loss buckets partition run time, so Bucket sum should equal Actual s/plate. The Sum − actual column should read 0.000 on every valid row. If it does not, the partition is missing a state.
